### 5.9 Gemini API 429 Quota Exhausted 및 모델 선택 정책
- **증상**: 데스크톱 MCP 사용 중 HTTP 429 (RESOURCE_EXHAUSTED) 에러가 발생하거나 gemini-3.6-flash 모델을 강제로 사용하여 쿼터가 즉시 소모됨.
- **원인**: 구글 AI Studio에서 gemini-flash-latest 등 최신 모델 호출 시(3.6 등) 무료 쿼터 제한을 20 RPM 등 매우 낮게 설정함. 기존 채팅창에서는 설정 변경 사항이 즉각 반영되지 않아 구형 모델을 계속 호출함.
- **해결책**: Hermes Desktop 설정(Settings)에서 모델을 gemini-1.5-flash 또는 gemini-flash-lite-latest로 직접 명시 후, **반드시 새로운 채팅창(New Session)**을 열어서 테스트해야 합니다.

### 5.10 컨테이너 재배포 시 SSH (2223포트) Connection Refused 문제
- **증상**: 윈도우 환경에서 deploy.py 등 스크립트를 사용하여 컨테이너를 재시작한 이후부터 ssh: connect to host port 2223: Connection refused 에러 발생.
- **원인**: 윈도우 PowerShell에서 파일을 쓸 때 눈에 보이지 않는 UTF-8 BOM 문자(3바이트)가 파일 시작 부분에 삽입됨. 리눅스 컨테이너 내부의 sshd가 sshd_config의 첫 단어 Port를 ort로 잘못 파싱하며 기동 실패.
- **해결책**: 윈도우 스크립트 파일 작성 시 반드시 UTF8NoBOM 인코딩 객체를 강제 주입하도록 수정되어 해결되었습니다.

### 5.11 오프라인(Unavailable) 센서로 인한 자동화 실패 원인 오진
- **증상**: 도어센서 등의 배터리가 방전되거나 연결이 끊어졌을 때(unavailable), AI가 이를 인지하지 못하고 다른 엉뚱한 원인(코드 버그 등)을 진단함.
- **해결책**: 백엔드 gemini_agent.py의 상태 요약 추출 로직에서 상태가 unavailable 또는 unknown인 기기 목록을 버리지 않고 요약본 하단에 명시적으로 노출하도록 개선하여 AI가 하드웨어 단선 원인을 정확히 추론할 수 있게 되었습니다.
